## Demo preparation

**Suggested flow:**
1. **Standalone app.** Log in through the popup. Show the list: search, family and status filters, sorting, paging. Open a product, edit it, create one, and delete one (it goes to the Recycle Bin).
2. **Prove it's live data.** Open the same product in standard Salesforce and show the change.
3. **Inside Lightning.** Open the **Product Manager** tab: it's the same app, embedded.
4. **Record page** (if open item 4 is done). Open a Product record, and the embedded app opens on that product.

**Talking points:**
- One React codebase runs both on its own and inside Lightning.
- There's no backend: the browser calls the Salesforce REST API directly.
- Login uses OAuth with PKCE, so there's no client secret anywhere.
- The UI uses the Salesforce Lightning Design System, so it looks native.
- Demo mode lets anyone try the app with no org at all.

**Before the demo:**
- **Log in twice in advance:** once on the standalone app and once in the tab. Browsers keep an iframe's storage separate, so each needs its own login.
- **Don't close the tabs.** The session lives in `sessionStorage`, so a closed browser tab means logging in again.
- **Allow popups** for `wise-moose-5sthg6-dev-ed.trailblaze.lightning.force.com`.
- **Use the production URL.** Vercel preview URLs aren't in the Trusted URL or CORS lists.
- **Fix the Product Family values** (open item 2). Ask the user before changing org data such as product families.
- **Prepare a fallback.** If the org or login fails, run the app in demo mode: run `npm run dev` with no `web/.env.local`, accept the local certificate at `https://localhost:5173`, and the app runs on sample data with no org.

## Rules

- **Only use the org `Servier - RnD React`.** Always pass `--target-org "Servier - RnD React"`, in quotes. Many client orgs are also connected on this machine.
  - Don't use `npm run sf:deploy`: it doesn't specify an org, so run `sf project deploy start` and `sf org assign permset` directly.
  - The alias `product-dev`, used in the npm scripts, is the same org, but the user asked for `Servier - RnD React` by name.
- **Ask the user first** before:
  - deploys
  - Setup changes
  - data changes in the org
  - `git commit` or `git push`
  - Vercel deploys
- **No client secret.** The Consumer Key is public (PKCE). Don't add a client secret anywhere.
- **`VITE_SF_LOGIN_URL` must be the My Domain URL** (`….my.salesforce.com`), never the `lightning.force.com` URL.
- **Redeploy after changing environment variables.** `VITE_*` values are built in at build time, so a change on Vercel needs a redeploy.
- **Never commit `web/.env.local`.**

1. The login screen appears, and **Log in with Salesforce** opens a popup.
2. After approval, the popup closes. The header shows "Connected to <host> as <name>".
3. **Read:** products are listed. Search, the family and status filters, sorting, and paging all work.
4. **Create:** the new product appears in the app and in Salesforce:

   ```bash
   sf data query -q "SELECT Id, Name FROM Product2 ORDER BY CreatedDate DESC LIMIT 5" --target-org "Servier - RnD React"
   ```

5. **Update:** change several fields, including clearing one (a blank field must become null), and check the result in Salesforce.
6. **Delete:** the product goes to the Recycle Bin. Deleting a product that a Pricebook entry uses should show Salesforce's error message in the dialog.
7. **Reload:** the session survives a page reload.
8. **Log out:** the login screen returns.

1. Open the **Product Manager** tab. Repeat steps 1–8 inside the iframe.

**C. Local dev in Lightning (optional)**
